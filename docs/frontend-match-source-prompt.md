# 给云端 AI 前端平台的实现提示词：检索结果命中来源提示

下面内容是一整段可直接粘贴给云端 AI 前端平台的提示词。它不包含待填写变量；文中的值均为已填实的中性占位示例，不是真实素材或真实目录。

---

请在现有视频素材检索前端中实现“检索结果命中来源提示”。只修改前端实现，不修改后端接口、后端字段、排序逻辑、测试或数据。使用已有组件、图标、字体和主题能力，不引入新的依赖。

## 一、产品目标

混合检索的结果可能来自两种召回通道：

- 语义通道：查询文字与画面特征的相似度，回答“画面里有什么”；
- 关键词通道：查询文字与素材文字信息的匹配，回答“素材叫什么”。

最终结果通过后端融合排序。用户需要在每条素材结果上快速看懂“这条为什么出现”，并在关键词命中时看到后端返回的实际命中文字。

结果列表是视频级列表：每行只展示一条素材，同一素材不能因为多个帧而重复出现。来源信息挂在素材行上，不能新增帧级结果列表。

## 二、接口契约

响应结构是 `data.results` 数组。每个结果对象可能包含以下新增字段：

- `match_type`：字符串，取值只能是 `semantic`、`keyword`、`both`；
- `matched_text`：字符串。关键词通道命中时是后端选出的实际命中片段，可能是文件名片段，也可能有意义的父目录名片段；纯语义结果为空字符串。

字段位于每个结果对象内，不在 `data` 顶层。字段不是所有响应都一定存在：

- 文本检索且关键词通道执行时，每条结果会有 `match_type` 和 `matched_text`；
- `semantic` 对应 `matched_text` 为空字符串；
- `keyword` 和 `both` 对应 `matched_text` 为非空字符串；
- 旧后端、关键词通道关闭、或以图搜图响应时，字段可能完全缺失；
- 缺少字段表示“当前响应没有这项提示”，不是错误，也不是自动等于 `semantic`。

请在前端做防御式读取：只接受合法的 `match_type` 字符串和字符串类型的 `matched_text`。字段缺失、类型不对或值非法时，省略对应的来源提示，不要让整个结果卡片失败。

## 三、文案映射

只使用下面三组固定中文文案，不要把 API 枚举直接展示给用户：

| API 值 | 可见文案 | 辅助技术完整文案 |
|---|---|---|
| `semantic` | 语义命中 | 命中来源：语义命中 |
| `keyword` | 关键词命中 | 命中来源：关键词命中 |
| `both` | 两路命中 | 命中来源：语义与关键词均命中 |

“命中来源”是来源行的固定小标签。命中文字的固定标签是“命中文字”。不要使用“文件名命中”或“目录名命中”，因为接口没有告诉前端片段类型。

## 四、卡片布局

请保留既有卡片的标题、缩略图、时长、分辨率、属性标签、预览、打开原片和复制路径行为。

在每条结果卡片中加入如下顺序：

1. 素材标题；
2. 独立的“命中来源”行；
3. 仅在有关键词文字时出现的“命中文字”证据行；
4. 既有时长、分辨率、属性标签行；
5. 既有操作区域。

示意结构如下。`material_file_sample` 和 `parent_segment_sample` 只是已填实的中性占位示例值：

```text
[素材标题：material_file_sample]
命中来源  [眼睛图标 语义命中]
命中文字  “parent_segment_sample”
[时长 00:42] [分辨率 1080P] [既有属性标签]
```

来源徽标必须放在独立行，不能放到标题末尾，不能混入时长、分辨率、属性标签所在的元信息行，也不要叠在缩略图的角标上。这样长标题不会挤压来源，来源不会被误读为素材属性，既有标签的数量、顺序和样式不需要改变。

窄屏时允许“命中来源”标签和徽标换行，不能覆盖标题、证据行或元信息；不能产生横向滚动。

## 五、命中来源徽标视觉规范

使用中性色 token，不绑定品牌。若没有现成 token，使用下面的浅色和深色回退值：

| 状态 | 浅色背景 | 浅色文字 | 浅色边框 | 深色背景 | 深色文字 | 深色边框 |
|---|---|---|---|---|---|---|
| semantic | `#E8EEF2` | `#1F2933` | `#52656F` | `#26333B` | `#E8F0F3` | `#9FB0B6` |
| keyword | `#F0ECE3` | `#4D3F2F` | `#756343` | `#3B342B` | `#F4EBDD` | `#C0AF91` |
| both | `#E6EFE8` | `#28513A` | `#4F7659` | `#293A30` | `#DCEEE0` | `#9BC0A5` |

建议将它们命名为 `source-semantic-surface`、`source-semantic-foreground`、`source-semantic-border`，以及对应的 keyword 和 both token。不要把这些值散落在组件各处；跟随已有主题系统切换。

尺寸和字阶：

- 字号 `12px`，行高 `16px`；
- 内边距 `4px 8px`；
- 图标与文字间距 `4px`；
- 圆角 `6px`；
- 最小高度 `24px`；
- `semantic` 字重 `500`；
- `keyword` 字重 `600`；
- `both` 字重 `700`；
- 三种状态均为 `1px` 边框、`semantic` 实线、`keyword` 虚线、`both` 实线。

非颜色冗余编码必须同时存在：

- semantic 使用单个眼睛或画面轮廓的线性图标；
- keyword 使用单个标签形或引号形的线性图标；
- both 使用两个相连节点或分叉形的线性图标；
- 三个图标都设置 `aria-hidden="true"`，可见文字承担含义；
- 视觉权重从强到弱为 `both`、`keyword`、`semantic`。徽标只解释来源，不改变 `rank` 或卡片顺序。

不要使用表情符号、仅颜色变化、仅透明度变化或只靠悬浮提示的方案。

## 六、命中文字展示

`matched_text` 是后端返回的实际片段。前端不区分文件名片段和目录名片段，也不通过扩展名、斜杠或猜测规则推断类型。

显示条件：

1. `match_type` 是 `keyword` 或 `both`；
2. `matched_text` 是非空字符串；
3. 该内容能作为纯文本安全显示。

显示方式：

- 放在“命中来源”行的下一行；
- 左侧固定显示“命中文字”；
- 右侧显示带视觉引号的原字符串，例如 `命中文字  “material_file_sample”`；
- 使用正文颜色、`12px/18px`、字重 `500`、低对比度浅色底和 `1px` 中性边框；
- 把字符串当纯文本，不解析 HTML，不补扩展名，不补路径层级，不改变大小写；
- 默认不是链接、按钮、展开控件或再次搜索入口；允许用户选择和复制文字；
- 可以在桌面使用浏览器原生 `title` 辅助，但完整字符串必须进入可访问名称，不能只依赖 `title`。

### 长字符串规则

按 Unicode code point 计数：

- 桌面最多显示 64 个 code point；
- 窄屏最多显示 40 个 code point；
- 桌面超过 64 个时显示前 24 个、`…`、后 39 个；
- 窄屏超过 40 个时显示前 15 个、`…`、后 24 个；
- 不超过上限时完整显示；
- 视觉截断不能改变 DOM 中的完整可访问字符串；
- 不能只用 CSS 的尾部省略代替中间省略；
- 不能把截断后的文字用于过滤、搜索或复制请求。

### 空值和异常值

- `matched_text` 为空字符串：不渲染命中文字行，不显示破折号或“未知”。
- `keyword` 或 `both` 的文字为空或类型异常：保留合法的来源徽标，但不渲染空白证据块。
- `semantic` 却带非空文字：忽略这段文字，不把语义结果误导成关键词证据。
- 非法 `match_type`：不渲染来源区。
- 只有 `matched_text` 而没有合法 `match_type`：不渲染来源区和命中文字区。

## 七、缺失字段与降级

前端必须能正常消费没有新字段的旧响应。若现有前端使用严格的旧响应类型或 JSON 解析器，请允许服务端增加的字段被忽略，不要把额外字段当成校验错误：

- 两个字段都缺失：不渲染“命中来源”行和“命中文字”行；
- 不显示空白徽标、空白证据块、占位符、骨架或错误提示；
- 不把缺失字段默认为 `semantic`；
- 不影响标题、缩略图、时长、分辨率、属性标签、预览、打开原片、复制路径、排序和键盘操作；
- 不因字段缺失而报错、崩溃或等待；
- 以图搜图响应缺少字段时，按旧响应处理，不显示来源徽标。

推荐状态矩阵：

| 输入状态 | 来源徽标 | 命中文字 | 卡片其余内容 |
|---|---|---|---|
| 字段全缺失 | 不显示 | 不显示 | 正常显示 |
| semantic + 空文字 | 语义命中 | 不显示 | 正常显示 |
| keyword + 非空文字 | 关键词命中 | 显示原文 | 正常显示 |
| both + 非空文字 | 两路命中 | 显示原文 | 正常显示 |
| keyword 或 both + 空文字 | 显示合法徽标 | 不显示 | 正常显示 |
| 非法字段 | 省略异常部分 | 省略异常部分 | 正常显示可处理结果 |

## 八、无障碍、主题与动效

- 徽标必须同时有可见中文文字和形状编码；不能只提供图标。
- 为来源组提供“命中来源：语义命中”“命中来源：关键词命中”“命中来源：语义与关键词均命中”的可访问名称；如果组件 API 需要显式属性，使用 `aria-label` 或 `aria-describedby` 补充。
- 图标使用装饰性标记并从读屏顺序隐藏。
- 命中文字即使视觉上被中间省略，也要让读屏得到完整原字符串，必要时用 `aria-label` 或隐藏的完整文本节点承载。
- 徽标和证据不是按钮，默认不进入 Tab 顺序；不得制造焦点陷阱。
- 普通文字与底色对比度至少 4.5:1；大字号文字、边框和焦点指示至少 3:1。
- 深色和浅色主题分别使用对应 token；不要只改透明度。
- 在 320px、768px、1440px 宽度下检查无重叠、无遮挡、无横向滚动。
- 可以让来源行随卡片一次性轻微淡入并上移，120–160ms；尊重 `prefers-reduced-motion`，关闭动画时仍立即显示最终内容。

## 九、实现约束

- 不改后端，不改 `scripts/05_api.py`，不改 API 地址，不改排序。
- 不新增依赖；优先使用已有图标、字体、布局和主题能力。
- 不改变视频级结果原则：每行一条素材，不把同一素材的多个帧重新铺成多行。
- 不创建新的标签字典、人工标签体系或额外筛选逻辑。
- 如果现有视觉系统的色阶名称不同，保留上述语义层级、文案、图标形状、对比度、响应式和降级行为，不要为了本功能另起一套风格。

## 十、生成后自检

实现完成后逐项检查：

1. 三个合法枚举都显示正确中文文案、图标和边框样式。
2. 灰度显示或关闭颜色后，仍能通过文字、图标形状和边框区分三种状态。
3. 来源行位于标题之后、既有元信息行之前，时长/分辨率/属性标签没有被重排或覆盖。
4. 关键词和两路结果能显示非空 `matched_text`，语义结果不显示证据行。
5. 长文本按 64/40 code point 规则中间省略，完整值仍可被读屏获取。
6. 空串、缺失、null、非法枚举和非字符串值都不会造成错误、空白占位或异常文字。
7. 旧响应和以图搜图响应仍能正常显示全部结果和既有操作。
8. 深色、浅色、320px、768px、1440px 下文字清晰且不重叠。
9. 结果仍是一行一条素材，来源提示没有改变后端排名。
10. 键盘、读屏和 reduced-motion 行为符合本提示词。
