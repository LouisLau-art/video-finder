# 检索结果命中来源提示：视觉与交互规格

> 状态：ready-for-agent
> 适用范围：混合检索结果卡片（每行一条素材）
> 脱敏说明：本文只使用中性占位示例值。`material_file_sample`、`parent_segment_sample` 是已填实的中性占位示例值，不是真实素材名、真实目录名或真实业务数据。

## 1. 目标与边界

混合检索的最终结果由「语义通道」和「关键词通道」融合而成。用户在结果卡片上需要快速知道两件事：

1. 这条素材是由哪一条或哪两条召回通道带出来的；
2. 如果有关键词通道命中，能否看到后端实际返回的命中文字片段，确认自己搜对了。

本规格只定义前端展示和交互，不改变后端响应、不改变融合排序、不引入新依赖。

领域词汇沿用 `CONTEXT.md`：

- **素材**：一条视频文件，是结果列表的最小业务单位；
- **语义通道**：用画面特征回答“画面里有什么”；
- **关键词通道**：用素材文字信息回答“素材叫什么”；
- **命中来源**：由 `match_type` 表示的通道组合；
- **视频级结果**：同一个素材只出现一次，附带代表帧和时间戳。

## 2. 结论摘要

- `match_type` 使用三个固定值：`semantic`、`keyword`、`both`。
- 采用独立「命中来源」行，放在标题之后、既有元信息行之前；不把来源徽标混入时长、分辨率、属性标签。
- `matched_text` 不区分文件名片段和目录名片段，因为后端没有提供这个判别字段；前端只把它当作不透明的实际命中文字。
- `matched_text` 只在 `match_type` 为 `keyword` 或 `both` 且字符串非空时显示，放在来源行的下一行。
- 徽标视觉权重排序为：`both` > `keyword` > `semantic`。排序仍由后端结果顺序决定，徽标不能改变排名。
- 新字段缺失时完全省略来源区和命中文字区，不显示空白框、破折号或“未知”占位；卡片、预览和其他操作照常工作。
- 以图搜图的实现当前不进入关键词分支，响应可能没有这两个字段；前端不能把缺少字段的结果擅自标成 `semantic`。

## 3. A：命中来源徽标

### 3.1 文案与非颜色编码

| API 值 | 可见文案 | 图标形状 | 边框辅助编码 | 面向用户的含义 |
|---|---|---|---|---|
| `semantic` | **语义命中** | 单个眼睛或画面轮廓，线性图标 | 1px 实线 | 由画面特征相似度召回 |
| `keyword` | **关键词命中** | 单个标签形或引号形，线性图标 | 1px 虚线 | 由素材文字信息召回 |
| `both` | **两路命中** | 两个相连节点或分叉形，线性图标 | 1px 实线，图标与文字组合最强 | 语义和关键词都召回 |

要求：

- 三种徽标始终同时显示中文文字和图标；不得只靠颜色、透明度或图标区分。
- 图标使用中性线性符号，不能使用表情符号；图标颜色跟随文字颜色，并设置 `aria-hidden="true"`。
- `both` 的辅助技术名称写成“命中来源：语义与关键词均命中”，视觉上仍显示较短的“两路命中”。
- 不把查询原文、分数或百分比放进徽标，避免徽标宽度随查询变化。

### 3.2 视觉 token 与尺寸

颜色使用中性色名，不绑定任何品牌。若平台已有色阶，优先映射到同义 token；若没有，以下十六进制值作为可验收的浅色与深色回退值。

| 语义 token | 浅色背景 / 文字 / 边框 | 深色背景 / 文字 / 边框 | 用途 |
|---|---|---|---|
| `source-semantic-surface` | `#E8EEF2` | `#26333B` | `semantic` 底色 |
| `source-semantic-foreground` | `#1F2933` | `#E8F0F3` | `semantic` 文字与图标 |
| `source-semantic-border` | `#52656F` | `#9FB0B6` | `semantic` 边框 |
| `source-keyword-surface` | `#F0ECE3` | `#3B342B` | `keyword` 底色 |
| `source-keyword-foreground` | `#4D3F2F` | `#F4EBDD` | `keyword` 文字与图标 |
| `source-keyword-border` | `#756343` | `#C0AF91` | `keyword` 边框 |
| `source-both-surface` | `#E6EFE8` | `#293A30` | `both` 底色 |
| `source-both-foreground` | `#28513A` | `#DCEEE0` | `both` 文字与图标 |
| `source-both-border` | `#4F7659` | `#9BC0A5` | `both` 边框 |

统一规格：

- 字号 `12px`，行高 `16px`，字间距 `0`；
- 内边距 `4px 8px`，图标与文字间距 `4px`；
- 圆角 `6px`，不使用高饱和大色块；
- 最小高度 `24px`，文字不换行；
- `semantic` 字重 `500`，`keyword` 字重 `600`，`both` 字重 `700`；
- 所有边框均为 `1px`，通过实线、虚线和图标形状再提供一层非颜色区分；
- 颜色只做辅助，文字、图标和边框样式必须足以让三种状态脱离颜色后仍可辨认。

上述回退值的文字与底色对比度均高于 4.5:1，边框与相邻底色对比度高于 3:1。深浅主题都必须使用对应的 surface、foreground、border 三组 token，不能只反转透明度。

### 3.3 视觉权重

排序规则如下：

1. **`both` 最醒目**：两种独立通道同时支持该素材，证据最强；使用最高字重和双节点图标。
2. **`keyword` 次醒目**：它是新增且最需要用户核对的线索；使用虚线边框和中高字重。
3. **`semantic` 最安静**：它是原有的大量基础结果，避免让整张结果卡片被普通状态占满注意力。

这不是置信度或新排序分数。卡片仍严格按后端 `rank` 展示；徽标只解释原因。

### 3.4 放置位置：独立「命中来源」行

选择：**标题行之后的独立徽标行**，位于既有时长、分辨率、属性标签行之前。

示意结构（`material_file_sample` 为中性示例值）：

```text
[素材标题：material_file_sample]
命中来源  [眼睛 语义命中]
命中文字  “parent_segment_sample”
[时长 00:42] [分辨率 1080P] [既有属性标签]
```

具体规则：

- 来源行的左侧显示固定小标签「命中来源」，再显示一个徽标；徽标不贴到标题末尾。
- 既有时长、分辨率、属性标签保持原位置、原顺序、原样式，来源徽标不加入它们的标签组。
- 来源行使用独立的垂直间距和底部边界；窄屏时允许「命中来源」和徽标自然换行，不允许覆盖标题或元信息。
- 命中文字证据行位于来源行之后、既有元信息行之前；它是解释性内容，不是另一个属性标签。
- 不把来源徽标叠在缩略图的相似度角标或时间角标上，避免两个角标竞争同一视觉焦点。
- 不使用“来源”“命中来源”等悬浮提示作为唯一说明；来源和含义必须在卡片上可见。

选择独立行的理由：

- **标题行**通常要承受长文件名和省略处理，追加徽标会使标题可读宽度变小，也容易让用户误以为徽标属于标题。
- **元信息行**已经承载时长、分辨率和属性标签。把来源放在那里会让用户误以为它是时长、格式或业务属性，也会造成标签换行和横向空间竞争。
- **独立行**把“为什么召回”与“素材是什么属性”分成两个语义组；既保留来源的可见性，又不改动既有信息架构。

### 3.5 视频级结果的影响

结果列表每行只展示一条素材，同一素材不能因为多个代表帧而重复出现。来源徽标、命中文字、代表帧时间戳都挂在这一行素材上：

- 不新增帧级来源列表；
- 不在卡片中重复渲染同一素材的多个 `match_type`；
- 关键词独有素材仍使用后端返回的 `score` 和代表帧，不因来源徽标改变数值显示；
- 排名、打开原片、复制路径、预览代表帧等既有操作保持不变。

## 4. B：`matched_text` 的展示

### 4.1 不区分文件名片段与目录名片段

前端**不需要也不应该区分**这两者。

判断依据：

1. 后端字段只有 `matched_text: str`，没有 `matched_text_type`、来源字段名或路径上下文。
2. 后端关键词索引把文件名去扩展名后的片段和有意义的父目录片段放在同一匹配流程中，最终只返回其中一个字符串。
3. 从字符串猜“它像文件名还是目录名”并不可靠：两类值都可能是普通文字，也可能没有扩展名、斜杠或其他稳定标记。
4. 误加“文件名命中”或“目录名命中”会把无法确认的事实呈现给用户，违反契约。

因此统一使用中性标签 **「命中文字」**，不要显示“文件名片段”“目录名片段”等未经后端确认的分类。

### 4.2 位置、样式与交互

- 位置：来源行正下方；只有 `match_type` 为 `keyword` 或 `both` 且 `matched_text` 为非空字符串时渲染。
- 可见结构：固定标签「命中文字」+ 带引号的值，例如 `命中文字  “material_file_sample”`。引号只是视觉边界，不属于后端字符串。
- 样式：使用正文文字颜色、`12px/18px`、字重 `500`；可使用低对比度的浅色底和 `1px` 中性边框，形成只读证据块。不要使用链接蓝、按钮蓝或高亮闪烁。
- 内容：把后端字符串作为纯文本原样渲染；不补扩展名、不补目录层级、不改斜杠、不做大小写转换、不根据它再次过滤结果。
- 交互：默认**不是按钮、链接或展开控件**。用户可以选择并复制文字；不要把它绑定到打开文件或再次搜索。允许使用浏览器原生 `title` 作为桌面辅助，但完整值必须同时进入可访问名称，不能只依赖 `title`。
- 若字符串含 HTML 字符，按纯文本显示，不能当作 HTML 解析。

### 4.3 超长字符串

按 Unicode code point 计数，避免把一个代理对字符截成乱码。采用中间省略，不只截尾，因为文件片段的开头和结尾都可能包含识别线索。

| 视口 | 最多显示的 code point 数 | 超长时的可见形式 |
|---|---:|---|
| 桌面宽度 | 64 | 前 24 个 + `…` + 后 39 个，共 64 个 |
| 窄屏宽度 | 40 | 前 15 个 + `…` + 后 24 个，共 40 个 |

规则：

- 长度不超过上限时完整显示，不加省略号。
- 超过上限时使用中间省略；不能使用只保留尾部的通用 CSS `text-overflow` 代替该规则。
- 完整原字符串仍保留在 DOM 的可访问名称或等价的屏幕阅读器文本中；视觉省略不能改变后端值。
- 不以像素宽度猜测字符数；视口断点由布局决定，长度规则按上表执行。
- 证据块保持单行，空间不足时换行到下一行并继续遵守同一字符上限，不产生横向滚动。

### 4.4 空值和异常值

- `matched_text` 为 `""`：不渲染命中文字行。`semantic` 的正常情况就是如此。
- `match_type` 为 `keyword` 或 `both` 但 `matched_text` 为空：仍可渲染对应来源徽标，但不显示空白证据块，也不猜测缺失原因。
- `match_type` 为 `semantic` 却带有非空 `matched_text`：忽略该文字，不把它显示为关键词证据。
- `match_type` 不是三个合法值：不渲染来源徽标；不报错、不阻断卡片其他操作。
- 字段类型不是字符串、值为 `null` 或只有空白时，按无可用证据处理；不要把对象转换成 `[object Object]`。
- `matched_text` 单独存在而 `match_type` 缺失或非法时，整段来源提示都不渲染。

## 5. C：降级与无障碍

### 5.1 字段缺失时的降级矩阵

| 响应状态 | 卡片来源区 | 命中文字区 | 其他结果内容 |
|---|---|---|---|
| 两个字段都缺失 | 整段不渲染 | 不渲染 | 正常显示 |
| `match_type=semantic`，`matched_text=""` | 显示「语义命中」 | 不渲染 | 正常显示 |
| `match_type=keyword`，文字非空 | 显示「关键词命中」 | 显示中性命中文字 | 正常显示 |
| `match_type=both`，文字非空 | 显示「两路命中」 | 显示中性命中文字 | 正常显示 |
| `match_type=keyword` 或 `both`，文字为空或异常 | 显示合法来源徽标 | 不显示空白行 | 正常显示 |
| 非法 `match_type`、非对象结果或字段类型异常 | 省略异常来源区 | 省略异常文字区 | 正常显示可处理的结果 |

旧后端、关闭关键词通道、或以图搜图响应没有新字段时，界面必须正常显示已有结果。若前端仍使用不认识新字段的旧响应类型或解析规则，额外的 JSON 字段应被忽略，不能触发校验错误。不得：

- 抛出前端异常或显示错误页；
- 等待字段后一直显示骨架；
- 留出空白徽标、空白证据行或 `—`；
- 把缺失字段默认为 `semantic`；
- 阻止预览、打开原片、复制路径或排序。

### 5.2 键盘与辅助技术

- 徽标始终有可见文字；图标只作装饰，设置为 `aria-hidden="true"`。
- 来源组使用语义容器或等价的可访问名称，读屏顺序为“命中来源：语义命中”“命中来源：关键词命中”“命中来源：语义与关键词均命中”。如果现有组件 API 需要显式属性，使用 `aria-label` 或 `aria-describedby` 补充，不要用它们隐藏可见文字。
- 命中文字的可见标签为“命中文字”；被视觉截断时，读屏仍应得到完整原字符串，必要时用 `aria-label` 或隐藏的完整文本节点承载。
- 徽标和命中文字默认不进入 Tab 顺序，不制造无意义的按钮焦点。
- 键盘用户可以到达卡片原有的预览、打开和复制操作；新增内容不能遮挡或改变原有焦点顺序。
- 不把颜色、图标或位置作为唯一信息来源；关闭 CSS、强制高对比度或色觉模拟时，文字和形状仍能表达来源。

### 5.3 对比度、主题与响应式

- 普通文字与底色至少达到 4.5:1；大字号文字、边框和焦点指示至少达到 3:1。
- 使用 `source-semantic-*`、`source-keyword-*`、`source-both-*` 三组语义 token；深色模式切换时同时替换背景、文字、边框和图标颜色。
- 禁止只改变透明度来适配深色模式；禁止把文字或图标放在无法确定对比度的图片上。
- 320px、768px、1440px 宽度下，来源行可换行但不能覆盖标题、命中文字或既有元信息；证据块不能造成横向滚动。
- 来源行可与卡片一起做一次轻微淡入上移动效，时长 120–160ms；尊重 `prefers-reduced-motion`，关闭时直接显示最终状态。动画不能延迟字段缺失时的正常渲染。

## 6. 实现边界

- 不修改 `scripts/05_api.py`、测试、向量库或任何后端数据。
- 不引入图标库、字体库或其他依赖；优先复用现有图标和 UI 字体。
- 不改变既有标题、时长、分辨率、属性标签、预览和路径操作的布局契约。
- 不把命中来源当成新的排序信号、筛选条件或人工标签体系。
- 若平台的既有设计系统与本规格的 token 名称不同，保留语义层级、中文文案、非颜色编码、对比度和降级行为即可，不为 token 名称另起一套视觉语言。
