# 索引宿主必须位于公司内网，通过 SMB 挂载 NAS

Status: accepted

## 决策

素材源存放在公司内网的群晖 NAS 上，NAS **没有公网地址**。索引管线（抽帧、图片编码、建库）需要对海量源文件做**文件系统级批量读取**，因此依赖把 NAS 通过 **SMB 协议挂载**成本地目录。

决策：**建索引的宿主必须身处公司内网**（当前为工位机），由它挂载 NAS、完成抽帧/编码/建库，再通过 rsync 把**索引成品**（向量库 + 缩略图）推送到公网服务器。公网服务器是索引成品的**纯消费者，永不直接访问 NAS**。

## 已核实的事实（含一次纠错）

- NAS 无公网地址；从公网服务器实测 NAS 的 SMB(445) 端口与 Web 管理端口均不可达。
- 群晖 **QuickConnect 中继对外网是可用的**——已验证：在公司网络之外用手机热点，经 `quickconnect.cn/<QC-ID>` 输入账号密码，成功登录 NAS 的 DSM / File Station 网页。
  - **更正**：早期曾误判「QuickConnect 没打通」，原因是只测了 QC 的**内网直连跳转域名**（它解析出 NAS 内网地址，仅在公司内网有效），没测真正的中继入口。准确表述见下条。
- 但 QuickConnect **只中转 DSM 网页与群晖官方客户端的流量，不中转 SMB**；且其浏览器登录依赖页面内 JS 二次握手，命令行工具无法完成。
- 结论：**QC 供「人 + 浏览器/App」可用，供「自动化管线」不可用。**

## 为什么不选其它路径

| 备选 | 结论 | 理由 |
|---|---|---|
| 公网服务器直接挂 SMB | ❌ 不可行 | NAS 无公网地址；SMB/Web 端口实测不可达；QC 直连域名解析为内网 IP |
| 用 QuickConnect 给管线供数 | ❌ 不可行 | QC 不中转 SMB；仅服务浏览器/官方 App；CLI 过不了 JS 握手 |
| Tailscale 组网（NAS + 内网常开机器） | ⚠️ 技术可行，暂不采用 | 需在 NAS 装套件、改管理员配置；大批源文件跨公网拉取慢；现有内网管线已满足需求，不值得增加复杂度 |
| Synology Drive Client 同步到云 | ⚠️ 不采用 | 绕、慢、占用双倍磁盘 |

## 影响

- **索引能力与「宿主在公司内网」强绑定**：宿主离开公司网络（换热点 / 在家）时 NAS 挂载失效，当晚增量索引会失败并被**如实记录**（不发布坏数据）。恢复：回到公司网 → 重新挂载 → 手动或等下一轮定时补跑。
- **安全优点**：NAS 不暴露公网；公网侧即使被攻破也接触不到源素材。
- **若将来要彻底摆脱对工位机的依赖**，唯一干净路径是 Tailscale 组网（NAS 与一台内网常开机器），而**不是**把 QuickConnect 用于自动化。
