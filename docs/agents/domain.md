# Domain Docs

各工程 skill 在探索本仓库时，应如何消费本仓库的领域文档。

## 探索之前，先读这些

- 仓库根目录的 **`CONTEXT.md`**，或
- 若存在 **`CONTEXT-MAP.md`**：它指向每个 context 各自的 `CONTEXT.md`。读取与你即将处理的主题相关的每一个。
- **`docs/adr/`**：读取与你即将动手的区域相关的 ADR。

若这些文件不存在，**静默继续**。不要指出它们缺失，也不要主动建议创建。
`/domain-modeling` skill（经 `/grill-with-docs` 与 `/improve-codebase-architecture` 到达）会在术语或决策真正被敲定时按需创建它们。

## 文件结构

本仓库是**单 context**：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── scripts/
```

## 使用词汇表里的词汇

当你的输出要命名某个领域概念时（issue 标题、重构提案、假设、测试名），使用 `CONTEXT.md` 中定义的术语。不要漂移到词汇表明确回避的同义词。

若你需要的概念还不在词汇表中，这是个信号：要么你在发明项目并不使用的语言（重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

若你的输出与某个既有 ADR 矛盾，明确提出来，而不是悄悄覆盖：

> _与 ADR-0007 矛盾，但值得重新讨论，因为……_
